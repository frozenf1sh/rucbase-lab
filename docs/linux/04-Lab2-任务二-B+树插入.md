## 1. 关键概念：叶子内的键值对挪动插入

B+树作为有序结构，它的每一个树节点的键值数组必须严格有序。为了维持连续数组的特性，每一次插入基本等同于一次顺序表的中间插入操作。

### 1.1 `insert_pairs` 批量插入与平移

由于键和值虽然是紧密相连甚至交叉对应的映射关系，但在底层的内存布局中是被切分为各自一块连续大数组管理。所以在节点内插入一段长度为 `n` 的新内容时：
1. **平移旧数据**：首先确定 `pos` 是在有效的 `[0, num_key)` 范围内，通过 `memmove` 将位于 `[pos, num_key)` 处的键与值全体向右平移 `n` 个单位的距离。利用 `tot_len` 控制着每一条字段的绝对占用字节数。
2. **存入新数据**：腾出的空当在 `[pos, pos+n)`，使用 `memcpy` 与 `set_rid` 进行填入。
3. **完成记录**：将该页的头部元数据 `num_key` 原子地增加 `n`。

### 1.2 `insert` 的单项包裹应用

借助于上个任务中构建好的 `lower_bound` 寻找最匹配的有序位置。如果在该位置检查出与新到的 key 完全相等，则直接无视丢弃（本系统默认无重复索引键策略），否则调用单元素的 `insert_pair` 进行平顺的植入。

## 2. 关键机制：满级分裂与生长

随着持续的数据插入，终有一刻一个节点的内部元素数量超过了其上限（对于多数非根节点为 `max_size`），此时就必定触发“树的生长”，也就是**中心分裂**（Split）。

### 2.1 `split` 的拦腰一刀

如何“劈开”一个节点？
1. 分配一个全新的节点页面成为这个旧结点的右侧新邻居。
2. 基于节点元素的一半得到一个锚点，将旧节点右半部分利用 `insert_pairs` 转移复制到新节点，并利用 `set_size` 把旧节点直接截断在锚点。
3. **特判处理**：
   - 叶子结点：就像链表一样操作 `prev_leaf` 与 `next_leaf` 将这个新生叶子插到双端底层链中。
   - 内部结点：子孩子的归属变了，我们需要挨个调用 `maintain_child` 让这批“外放”数据的对应底层孩子的 parent 指向新的 node。

### 2.2 `insert_into_parent` 分裂波及

分裂结束就完了吗？并没有，因为右边的新节点是一个凭空出现的新子树区域，这使得它的“代表符/锚键”（新节点的第0个键）必须要作为新的隔离栅栏加入到原本的上一级父节点内。
此时的递归精妙之处在于：
1. 若目前的分裂本体**本身就是根节点**，那说明整棵树已经达到饱和的极大值，我们需要新造一个高度更上一层的伪内部结点成为新的 Root，并把它作为那两者的共同唯一父亲，结束递归扩张。
2. 然而只要它是普通的节点，找到那个父节点，将这把新的栅栏钥匙插入到旧儿子所属序列 `child_idx + 1` 后方。
3. 可是一旦这导致了父亲这个内部结点也被迫满载，我们将继续对这名父节点引发递归。

这完美诠释了 B+ 树**自底向上生长**的核心思想。

### 2.3 `insert_entry` 主干枢纽

整体框架组合如下：
如果树刚被开启，第一次建立根节点插入第一道数据，记录起 `first_leaf_` 与 `last_leaf_` 的全局轨迹。
否则调用 `find_leaf_page`（此处 `operation` 用 `INSERT` 以做并发读写锁区分防越限），获取底层那个原本就有义务容纳当前值的叶子结点进行 `insert` 任务，若返回结果导致该叶子结点超重了，随同执行波及全树的“满级生根”。
每一次页面经历更改返回前都务必打上重重的不变式 `is_dirty = true`。
